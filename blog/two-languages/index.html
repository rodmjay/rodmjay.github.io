Every post here ships in two languages

Why a post waits until the Spanish is written too, and how a simple build enforces it.

November 21, 20264 min readLeer en español

On this page
  1. Why both, every time
  2. The file
  3. How a post moves

This blog is a folder of markdown files in the same repository as the rest of the site. A small build turns them into pages, and GitHub Pages serves them. Every post has an English and a Spanish version, and neither goes live alone.

#Why both, every time

Many of the people I work with read Spanish first. A machine translation reads like one, so each version is written by hand, and the site never shows a language switch that leads to a missing page.

  • Each post is two files that share an id.
  • Either one can wait as a draft.
  • The build stops if a live post has no twin.

Writing it twice is the point. The second pass catches what the first one hid.

Notes from the first post

#The file

The front matter carries everything the index needs. The id is what ties the English file to its Spanish twin.

Publishing is two commands:

node scripts/build-blog.mjs   # fails if a live post has no twin
git push                         # GitHub Pages publishes it
